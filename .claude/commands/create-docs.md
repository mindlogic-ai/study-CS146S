# Generate API Documentation

Create or update API documentation by analyzing the actual codebase.

Target: $ARGUMENTS (e.g., "backend/app/routers" or a specific router file, or "all" for everything)

## Steps

### 1. Discover Endpoints

- Find all router files by searching for `APIRouter()` or `@router.` / `@app.` decorators
- For each endpoint, extract: HTTP method, path, function name, status code, response model
- Check for query parameters, path parameters, and request body schemas

### 2. Analyze Schemas

- Find Pydantic model definitions (classes inheriting from `BaseModel`)
- For each schema, extract: field names, types, defaults, validation rules (Field constraints)
- Note which schemas are used as request bodies vs response models

### 3. Check Existing Documentation

- Read the current `docs/API.md` if it exists
- Note what endpoints were previously documented
- Track additions, removals, and changes for the delta report

### 4. Generate Documentation

Write `docs/API.md` with this structure:

```markdown
# API Documentation

> Auto-generated by `/create-docs`

## Endpoints

### [Resource Name]

| Method | Path | Description | Status |
|--------|------|-------------|--------|
| GET | /resource/ | List all | 200 |

#### GET /resource/
- **Query params:** ...
- **Response:** `SchemaName`

### Schemas

| Field | Type | Required | Constraints |
|-------|------|----------|-------------|
```

### 5. Report Changes

Output a summary:
- Total endpoints documented
- New endpoints (vs previous docs)
- Removed endpoints (vs previous docs)
- Schemas documented

## Guidelines

- Read the actual code, not assumptions
- Include error responses (404, 422) where applicable
- Document query parameters with their defaults
- Keep it concise — developers should be able to scan quickly
